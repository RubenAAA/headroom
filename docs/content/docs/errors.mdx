Headroom provides explicit exceptions for debugging, with a core safety guarantee: **compression failures never break your LLM calls**. If compression fails, the original content passes through unchanged.

## Error hierarchy

The Rust proxy surfaces errors as HTTP statuses on the forwarded routes, plus structured bodies on the local endpoints (`/healthz`, `/ctx/doctor`, `/cache-health`). The old Python exception classes (`HeadroomError`, `HeadroomConnectionError`, `HeadroomAuthError`, provider/storage/compression errors) live in the read-only `upstream-python/` mirror.

Common cases:

- Cannot reach proxy → connection refused on 8787; check `curl -s localhost:8787/healthz` and whether the proxy is running.
- 401 from upstream → the provider key or auth mode is wrong; see [Troubleshooting](/docs/troubleshooting).
- 404 on a local endpoint → wrong path (e.g. `/health` instead of `/healthz`).

## Error types in detail

The Python exception reference (`ConfigurationError`, `ProviderError`, `StorageError`, `CompressionError`, `HeadroomConnectionError`) lives in the read-only `upstream-python/` mirror. On the Rust proxy, the equivalent signals are HTTP statuses and the `tracing` log (`headroom-proxy.log`): a failed transform passes the original content through unchanged rather than failing the request.

## Safety Guarantee

If compression fails, the original content passes through unchanged. Your LLM calls never fail due to Headroom:

```python
messages = [
    {"role": "tool", "content": "malformed json {{{"}
]

# This will NOT raise an exception
# The malformed content passes through unchanged
response = client.chat.completions.create(
    model="gpt-4o",
    messages=messages,
)
```

## Best practices

1. **Validate on startup** with `curl -s localhost:8787/healthz` and `headroom doctor`.
2. **Enable logging** — the proxy log shows when compression falls back safely.
