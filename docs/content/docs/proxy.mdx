The Headroom proxy is a standalone Rust HTTP server (`crates/headroom-proxy`, binary `headroom-proxy`). Point any client at it and get cache stabilization, compression, and observability on every turn. It is a transparent reverse proxy: it forwards to the upstream provider and optimizes the traffic passing through.

Start it via the launcher (`cclaude --context`, which starts the proxy if nothing listens on 8787), or directly:

```bash
headroom-proxy --listen 127.0.0.1:8787 --upstream https://api.anthropic.com
```

> Run `headroom-proxy --help` for the authoritative flag list (144 flags). Every flag also has a `HEADROOM_PROXY_*` environment variable, and the full generated reference lives in `docs/flags.md`. The measured set the maintainer runs is `contrib/headroom-flags.sh`, copied to `~/.headroom-flags.sh` by `install.sh`.

## Starting the proxy

```bash
# Basic usage
headroom-proxy --upstream https://api.anthropic.com

# Custom host and port
headroom-proxy --listen 127.0.0.1:8787 --upstream https://api.anthropic.com
```

The flags in effect are the ones the running process started with — a proxy already listening on 8787 is reused, so editing `~/.headroom-flags.sh` alone changes nothing until `restart-headroom.sh`.

## Forwarded routes

The proxy forwards provider traffic and optimizes it in flight:

- Anthropic: `/v1/messages`, `/v1/messages/batches/*`, `/v1/messages/count_tokens`, `/v1/models`, `/anthropic/v1/messages`
- OpenAI: `/v1/chat/completions`, `/v1/responses`, `/v1/batches/*`, `/v1/conversations/*`
- Bedrock: `/model/{model_id}/converse`, `/invoke`, and streaming variants; Vertex: `/v1beta/...`
- Codex: `/v1beta/models/*`

Point the client at the proxy address (e.g. `ANTHROPIC_BASE_URL=http://localhost:8787`) and use it normally.

## Local endpoints

Served by the proxy itself, not forwarded:

- `GET /healthz` — liveness ground truth (`{"ok":true}`)
- `GET /healthz/upstream`, `/livez`, `/readyz` — upstream and readiness checks
- `GET /cache-health` — hit rates and recent cache events
- `GET /metrics`, `/stats`, `/stats-history`, `/stats-lifetime` — observability (see [Metrics](/docs/metrics))
- `GET /debug/inflight` — turns currently generating (used by `restart-headroom.sh` to wait for a clean drain)
- `/ctx/*` (`search`, `get`, `index`, `fetch`, `stats`, `doctor`, `purge`) — context offload and retrieval
- `/mcp/{conversation}` — MCP tools (`headroom_compress`, `headroom_retrieve`, `headroom_stats`)

## Restarting

```bash
restart-headroom.sh            # waits for in-flight turns, then restarts onto a fresh build
restart-headroom.sh --force    # skip the drain wait
restart-headroom.sh --wait-secs=300
```

Restarts are safe but not free: in-flight turns past the graceful drain truncate, and per-process pins re-latch (see `contrib/restart-headroom.sh` header). Restart when nothing is mid-turn.
